# הדף השבועי של בני עקיבא — תשפ"ז

אפליקציה סטטית (PWA) לתוכנית הדף השבועי: דף בשבוע, מסכת שלמה בשנה.
כל ישיבה בוחרת מסכת תענית, מסכת מגילה, או את שתיהן.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | האפליקציה כולה — מסכים, מנוע המצגת, החידה |
| `data.js` | **כל התוכן.** לוח השנה, המוסדות, המצגות והחידות |
| `links.js` | קישורי צורת הדף והחברותא, מיובא מ"יגדיל תורה" |
| `slides/` | שקפי המצגות כתמונות, תיקייה לכל שבוע |
| `sfarim/` | תמונות הגמרות — כריכה ופריסת עמודים לכל מהדורה |
| `logo.js` | הלוגו הרשמי של בני עקיבא, מוטמע כ-base64 |
| `vercel.json` | ניתוב `/admin` וכלל מטמון |
| `sw.js` | Service Worker — פתיחה מיידית ועבודה בלי רשת |
| `manifest.json` | הגדרות PWA להתקנה במסך הבית |

## עדכון תוכן שבועי

הכול ב-`data.js`. אין צורך לגעת בקוד.

```js
CONTENT['megila-7'] = {          // taanit או megila, ומספר השבוע (1–36)
  title: 'כותרת הדף',
  deck: { dir:'slides/megila-7', n:12 }    // מצגת תמונות — העדיפות
};
QUIZ['megila-7'] = { q:'השאלה', a:['א','ב','ג','ד'], correct:1 };
```

### הוספת מצגת חדשה

מייצאים את קובץ ה-PowerPoint ל-PDF, וממירים לתמונות:

```sh
mkdir -p slides/megila-7
pdftoppm -jpeg -jpegopt quality=80 -r 96 deck.pdf slides/megila-7/s
cd slides/megila-7 && i=1
for f in $(ls s-*.jpg | sort -V); do mv "$f" "$(printf '%02d.jpg' $i)"; i=$((i+1)); done
```

התוצאה 1920×1080, בערך 180KB לשקף. אחר כך מוסיפים `deck:` ל-`CONTENT`.

אין צורך להגדיל את השקפים: נגן המצגת הוא `object-fit:contain`, ולכן
רזולוציית המקור מספיקה והגדלה רק מנפחת את הקבצים. `slides/taanit-1`
נשמר ב-1376×768 המקוריים — עשרה שקפים, 1.1MB בסך הכול.

אם אין `deck` אבל יש `slides: [{k,h,t},…]` — האפליקציה מרנדרת מצגת טקסט
בעיצוב התוכנית. שימושי לשבוע שאין לו עדיין מצגת מעוצבת. כששניהם
קיימים `deck` מנצח, וה-`slides` נשאר כגיבוי.

**הכפתורים במסך הבית נגזרים מזה.** שבוע עם `deck` מקבל
"▶ הצגה על המסך" + "הדף"; בלעדיו — "לדף ולחומרי הלימוד" + "המסלול".
אין קוד נפרד לכל מסלול.

## עדכון גרסה

מעלים את `APP_VERSION` ב-`index.html`. **זהו.**
`CACHE_NAME` ב-`sw.js` נגזר ממנו אוטומטית בסקריפט הבנייה — כי
גרסת מטמון שנשכחה גורמת למכשיר להגיש `index.html` ישן יחד עם
`data.js` חדש, וזה שובר מסכים שלמים.

**אסטרטגיית המטמון:** קבצי קוד (`index.html`, `*.js`) נטענים
**מהרשת קודם** ורק בכישלון מהמטמון — כך גרסה תקועה לא יכולה
להישאר. שקפים ואייקונים נטענים מהמטמון קודם, כי הם כבדים ולא
משתנים בשקט. אופליין ממשיך לעבוד בשני המקרים.

## מסך הניהול — `/admin`

**אין אליו שום קישור באפליקציה.** נגיש רק בכתובת ישירה:
`…/admin` (או `#admin`), ואחריה קוד בן 4 ספרות.
ברירת המחדל ב-`ADMIN_PIN` שב-`data.js`, וניתן לשנות אותה מתוך המסך.

שישה מקטעים: הרשמות שהתקבלו · מוסדות (מי מופיע כ"בפנים") ·
מוקד שיחות · מחירים · הסוגיה היומית (כתובת הפליפבוק ומיפוי העמודים) ·
הגדרות (וואטסאפ, כתובת שרת, קוד, גיבוי).

כל הכתיבות עוברות דרך `Store`. להחלפת המנוע לשרת מרוחק צריך
למלא `Store.push` — שאר הקוד לא משתנה.

אנשי הקשר **אינם בקוד**. הריפו ציבורי, ולכן מספרי טלפון של מנהלים
נשמרים ב-localStorage של המכשיר בלבד: מדביקים פעם אחת את השורות
מגיליון הגוגל, והרשימה נשמרת מקומית. כפתור "מחיקת הרשימה מהמכשיר"
מנקה הכול.

לכל מוסד: חיוג ישיר, וואטסאפ, סטטוס (לא דיברתי / דיברתי / מתעניין /
הצטרף / לא השנה) והערה חופשית. המוסדות שלמדו בתשפ"ו מוצגים ראשונים.

## מסלולים, המלצה ומחירים

**אין שיוך לכיתות.** כל ישיבה בוחרת מסכת אחת — תענית או מגילה —
או את שתיהן. `TRACKS` ב-`data.js` מחזיק רק `masechet`, ואין באפליקציה
שום אזכור של כיתה ז׳ או ח׳.

### סדר מסך ההרשמה

1. **שלוש דרכים ללמוד** · 2. **מה כדאי לנו לרכוש?** ·
3. **כמה זה עולה לנו** · 4. **מי אתם?**

"מי אתם" הוא אחרון בכוונה: אף אחד לא משאיר שם וטלפון לפני שהוא
יודע למה, והחששות נענים בדרך למטה. למי שכבר נרשם מופיעה למעלה
שורת `.jump` שגוללת ישר לסעיף 4.

### שלוש דרכים ללמוד

`WAYS` ב-`data.js`. זה החלק הראשון שראש חטיבה רואה, והוא עונה על
החשש שעוצר אותו — "מי מאנשי הצוות שלי יוביל את זה?" — בכך שאין
צורך: בהפסקות, אבא ובן, או תלמיד שלומד לבד. `WAYS.more` מקשר
לאפליקציית **יגדיל תורה** (`yagdil-torah.netlify.app`), כרגע כאזכור
בלבד; ההטמעה בשפה העיצובית שלנו תיעשה בהמשך.

### ההמלצה

`SFARIM[].rec` הוא המשפט שמופיע לראש החטיבה, בגוף שני, כפי שהוא
נאמר בטלפון. מתחתיו הספר: הכריכה בגודלה הטבעי (`pics[].small` —
מתיחה מעבר לו רק מרככת אותה), ומתחתיה **הפריסה הפתוחה ברוחב מלא**.
זו התמונה שממנה מתרשמים. `fit` הוא אותו דבר בשתי מילים, לשורת
ההזמנה.

**לחיצה על תמונה מגדילה אותה** לשכבת `#zoom`, ושם היא נפתחת
**בגודלה המקורי ולא מוקטנת למסך**: בנייד "התאמה למסך" הייתה
מחזירה אותה כמעט לגודל שבכרטיס, ואז ההגדלה לא מוסיפה כלום. גדולה
מהמסך → גוללים אליה.

היה פעם מסך ספרים נפרד; הוא נמחק כי שום כפתור לא הוביל אליו, ולכן
התמונות פשוט לא נראו לאיש.

**התמונות ב-`sfarim/` הן JPEG.** קובץ מקור ב-AVIF או WebP יש להמיר
— ספארי בגרסאות ישנות לא מציג אותם, וראש חטיבה אחד יראה ריבוע ריק.

### המחירים

`PRICES` ב-`data.js` נותן לכל מהדורה שלושה מספרים:

```js
veshinantam: { price: 15, list: 25, min: 400 },
sugya:       { price: 22, list: 25, min: 300 }
```

`price` — בהזמנה מרוכזת · `list` — המחיר הרגיל ·
`min` — **כמה עותקים צריך כדי שההנחה בכלל תינתן.**

כל מסך שמציג מחיר עובר דרך `priceOf(id)`, ואין באפליקציה שום סכום
קשוח. `min` נספר על **שתי המסכתות יחד**, כי ההוצאה סופרת עותקים
ולא כרכים — זה מה ש-`sefTotal()` עושה.

### תנאי הכמות

`condNote()` מדפיסה את התנאי **צמוד למחיר של המהדורה שלו**, בתוך
כרטיס ההמלצה. בלי זה מבטיחים לראשי החטיבות מחיר שעדיין לא הובטח.
שתי ההערות אינן נערמות זו אחרי זו בתחתית — כל אחת ליד הספר שלה.
`min:0` מבטל את ההערה לאותה מהדורה.

מלבן הסיכום מציג את הסכום ואת החיסכון בלבד. פירוט הכמויות נמצא
בשורות שמעליו, וחזרה עליו רק מעמיסה.

במסך הניהול, לשונית **מחירים**: שלושה שדות לכל מהדורה. הערכים
נשמרים ב-`CFG.prices` ו-`applyCfg` **ממזג** אותם לתוך `PRICES`
שדה-שדה, כדי שהגדרה ישנה שנשמרה במכשיר לא תמחק שדה שהתווסף מאז.

### מבנה ההזמנה

`reg.qty` ממופתח `'<מסכת>-<מהדורה>'` — ארבעה מספרים. זו גם התשובה
ל"כמה תלמידים", ולכן אין שאלה נפרדת. הפילוח לפי מסכת הוא מה שקובע
כמה כרכים מזמינים מכל אחת.

אין שדה הערה חופשית: מה שצריך לברר מתברר בשיחת הטלפון.

`regMigrate()` מטפל בשתי צורות ישנות של הרשמה שמורה: `z`/`ch` עם
מהדורה אחת (z היה תענית ו-ch מגילה, ולכן ההעברה מדויקת), ו-`qty`
לפי מהדורה בלבד בלי מסכת — צורה שחיה שעות ספורות, ואין בה מידע על
המסכת, ולכן היא נכנסת לתענית וצריך לוודא אותה בשיחה.

## קישור לפי מוסד

`?m=<code>` משייך את מי שנכנס למוסד שלו מראש — למשל `?m=raanana`.
הקודים נמצאים ב-`INSTITUTIONS` בתוך `data.js`.

## כתיבה לגיליון

`APPS_SCRIPT_URL` ב-`data.js` מצביע על ה-Web App שקוד המקור שלו
ב-`apps-script.gs`. הרשמות נכתבות ללשונית "הרשמות", תשובות חידה
ללשונית "חידות" — שתיהן נוצרות לבד בפעם הראשונה.

השליחה היא `mode:'no-cors'` כי Apps Script אינו מחזיר כותרות CORS.
לכן אין אישור מהשרת: כשל רשת משאיר את הפריט בתור וניסיון חוזר
יתבצע אחר כך, אבל שגיאה בצד השרת תיראה כהצלחה. לבדיקת חיים —
פתיחת ה-URL בדפדפן אמורה להחזיר `{"status":"ok"}`.

**הכתובת חייבת לשבת ב-`data.js`.** שדה "כתובת שרת" במסך הניהול
נשמר על מכשיר אחד בלבד, וראשי החטיבות פותחים במכשירים שלהם.

## פרסום כ-Artifact

עמוד Artifact נעטף אוטומטית ב-`<!doctype html><head></head><body>`.
לכן **אין לשלוח מסמך HTML שלם** — התגיות הפנימיות מבוטלות, `.app`
מאבד את הקשר ה-flex שלו, והפריסה נשברת. יש להפיק *קטע* בלבד:
ה-`<style>` ותוכן ה-`<body>`.

מאותה סיבה `dir="rtl"` שעל תגית `<html>` נעלם, ולכן העמוד קובע
אותו מהקוד בתחילת ה-body.
