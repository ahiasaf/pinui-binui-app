# הדף השבועי של בני עקיבא — תשפ"ז

אפליקציה סטטית (PWA) לתוכנית הדף השבועי: כיתות ז׳ לומדות מסכת תענית,
כיתות ח׳ מסכת מגילה — דף בשבוע, לאורך כל השנה.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | האפליקציה כולה — מסכים, מנוע המצגת, החידה |
| `data.js` | **כל התוכן.** לוח השנה, המוסדות, המצגות והחידות |
| `links.js` | קישורי צורת הדף והחברותא, מיובא מ"יגדיל תורה" |
| `slides/` | שקפי המצגות כתמונות, תיקייה לכל שבוע |
| `logo.js` | הלוגו הרשמי של בני עקיבא, מוטמע כ-base64 |
| `vercel.json` | ניתוב `/admin` וכלל מטמון |
| `sw.js` | Service Worker — פתיחה מיידית ועבודה בלי רשת |
| `manifest.json` | הגדרות PWA להתקנה במסך הבית |

## עדכון תוכן שבועי

הכול ב-`data.js`. אין צורך לגעת בקוד.

```js
CONTENT['megila-7'] = {          // taanit או megila, ומספר השבוע (1–36)
  title: 'כותרת הדף',
  deck: { dir:'slides/megila-7', n:12 }    // מצגת תמונות — העדיפות
};
QUIZ['megila-7'] = { q:'השאלה', a:['א','ב','ג','ד'], correct:1 };
```

### הוספת מצגת חדשה

מייצאים את קובץ ה-PowerPoint ל-PDF, וממירים לתמונות:

```sh
mkdir -p slides/megila-7
pdftoppm -jpeg -jpegopt quality=80 -r 96 deck.pdf slides/megila-7/s
cd slides/megila-7 && i=1
for f in $(ls s-*.jpg | sort -V); do mv "$f" "$(printf '%02d.jpg' $i)"; i=$((i+1)); done
```

התוצאה 1920×1080, בערך 180KB לשקף. אחר כך מוסיפים `deck:` ל-`CONTENT`.

אם אין `deck` אבל יש `slides: [{k,h,t},…]` — האפליקציה מרנדרת מצגת טקסט
בעיצוב התוכנית. שימושי לשבוע שאין לו עדיין מצגת מעוצבת.

## עדכון גרסה

מעלים את `APP_VERSION` ב-`index.html`. **זהו.**
`CACHE_NAME` ב-`sw.js` נגזר ממנו אוטומטית בסקריפט הבנייה — כי
גרסת מטמון שנשכחה גורמת למכשיר להגיש `index.html` ישן יחד עם
`data.js` חדש, וזה שובר מסכים שלמים.

**אסטרטגיית המטמון:** קבצי קוד (`index.html`, `*.js`) נטענים
**מהרשת קודם** ורק בכישלון מהמטמון — כך גרסה תקועה לא יכולה
להישאר. שקפים ואייקונים נטענים מהמטמון קודם, כי הם כבדים ולא
משתנים בשקט. אופליין ממשיך לעבוד בשני המקרים.

## מסך הניהול — `/admin`

**אין אליו שום קישור באפליקציה.** נגיש רק בכתובת ישירה:
`…/admin` (או `#admin`), ואחריה קוד בן 4 ספרות.
ברירת המחדל ב-`ADMIN_PIN` שב-`data.js`, וניתן לשנות אותה מתוך המסך.

חמישה מקטעים: הרשמות שהתקבלו · מוסדות (מי מופיע כ"בפנים") ·
מוקד שיחות · הסוגיה היומית (כתובת הפליפבוק ומיפוי העמודים) ·
הגדרות (וואטסאפ, כתובת שרת, קוד, גיבוי).

כל הכתיבות עוברות דרך `Store`. להחלפת המנוע לשרת מרוחק צריך
למלא `Store.push` — שאר הקוד לא משתנה.

אנשי הקשר **אינם בקוד**. הריפו ציבורי, ולכן מספרי טלפון של מנהלים
נשמרים ב-localStorage של המכשיר בלבד: מדביקים פעם אחת את השורות
מגיליון הגוגל, והרשימה נשמרת מקומית. כפתור "מחיקת הרשימה מהמכשיר"
מנקה הכול.

לכל מוסד: חיוג ישיר, וואטסאפ, סטטוס (לא דיברתי / דיברתי / מתעניין /
הצטרף / לא השנה) והערה חופשית. המוסדות שלמדו בתשפ"ו מוצגים ראשונים.

## קישור לפי מוסד

`?m=<code>` משייך את מי שנכנס למוסד שלו מראש — למשל `?m=raanana`.
הקודים נמצאים ב-`INSTITUTIONS` בתוך `data.js`.

## כתיבה לגיליון

`APPS_SCRIPT_URL` ב-`data.js` מצביע על ה-Web App שקוד המקור שלו
ב-`apps-script.gs`. הרשמות נכתבות ללשונית "הרשמות", תשובות חידה
ללשונית "חידות" — שתיהן נוצרות לבד בפעם הראשונה.

השליחה היא `mode:'no-cors'` כי Apps Script אינו מחזיר כותרות CORS.
לכן אין אישור מהשרת: כשל רשת משאיר את הפריט בתור וניסיון חוזר
יתבצע אחר כך, אבל שגיאה בצד השרת תיראה כהצלחה. לבדיקת חיים —
פתיחת ה-URL בדפדפן אמורה להחזיר `{"status":"ok"}`.

**הכתובת חייבת לשבת ב-`data.js`.** שדה "כתובת שרת" במסך הניהול
נשמר על מכשיר אחד בלבד, וראשי החטיבות פותחים במכשירים שלהם.

## פרסום כ-Artifact

עמוד Artifact נעטף אוטומטית ב-`<!doctype html><head></head><body>`.
לכן **אין לשלוח מסמך HTML שלם** — התגיות הפנימיות מבוטלות, `.app`
מאבד את הקשר ה-flex שלו, והפריסה נשברת. יש להפיק *קטע* בלבד:
ה-`<style>` ותוכן ה-`<body>`.

מאותה סיבה `dir="rtl"` שעל תגית `<html>` נעלם, ולכן העמוד קובע
אותו מהקוד בתחילת ה-body.
